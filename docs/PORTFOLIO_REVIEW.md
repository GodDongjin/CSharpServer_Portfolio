## 설명할 설계

세션 반환 시 I/O·비동기 작업의 수명과 연결 ID를 함께 확인하는 이유, Hero 커밋 후 메모리 반영 순서, 결과 불명확 시 재로그인으로 DB를 다시 읽는 이유, 매칭 취소·성립·종료의 직렬화와 Redis 토큰의 역할을 설명합니다. 직접 작성한 자동 생성 도구는 기존 구현을 유지하면서 패킷 ID·등록·새 핸들러를 생성합니다.

## 추가 검증 범위

실제 Redis 재시작·토큰 불일치·TTL 만료, 커밋 응답 유실, DB 작업 진행 중 종료 등의 장애 주입은 추가 검증 항목입니다. 현재 확인된 결함 목록이 아닙니다. 다중 서버 정합성, 외부 네트워크 최대 성능, 모바일 백그라운드는 검증 범위에 포함하지 않습니다.
