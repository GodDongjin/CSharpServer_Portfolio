# 로컬 부하 테스트 결과

검증일: 2026-10-07. 실제 MySQL·Redis를 사용한 14개 시나리오에서 측정 실패 0건. 원본 결과 JSON을 바탕으로 복구한 기록이며, 2026-10-12 공개본 정리 중 다시 실행한 부하 시험은 아닙니다.

## 조건

- Windows Debug/net10.0, Docker MySQL 8.4·Redis 7.4, 서버와 Python 클라이언트가 동일 PC에서 loopback으로 통신.
- 최대 세션 100개, DB Worker 4개, DB 연결 풀 최대 20개.
- Hero 단계는 약 8초씩 1회 측정. 클라이언트마다 응답을 기다린 뒤 다음 요청을 보냅니다. 로그인 준비 시간은 제외합니다.
- 조회는 로그인 시 읽은 메모리 캐시, 변경은 실제 DB 트랜잭션. 혼합 단계는 조회 4회·저장 1회 반복.
- 지연은 클라이언트 송신부터 응답 내용 확인까지입니다. 로그 I/O와 부하 생성기의 자원 사용이 포함됩니다.

저장 동시성을 늘려도 약 334건/초에 머물고 지연이 증가했습니다. 해당 환경에서 대기가 쌓이는 징후이며, 별도 프로파일링 없이 병목 원인을 단정하지 않습니다. 최고 처리량을 운영 최대 성능으로 사용하지 않습니다.

원본은 로컬 TestResults/LoadReview/results.json 및 cancel-results.json입니다. 실행기·원본 로그는 공개본에서 제외했습니다. 외부 네트워크, 느린 수신자, 저장소 장애 주입은 포함하지 않았습니다.
